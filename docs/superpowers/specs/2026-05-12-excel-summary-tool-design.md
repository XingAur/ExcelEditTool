# ExcelEditTool 设计

## 目标

构建一个给财务使用的本地 Excel 表格处理工具。用户通过浏览器界面选择本地 `.xlsx` 文件，切换 sheet，预览原始数据，自定义分组列和求和列，生成汇总结果，预览新结果表，并支持带格式复制到 Excel 或导出新的汇总文件。

## 第一版范围

- 选择本地 `.xlsx` 文件。
- 读取 workbook 内所有 sheet，并支持 sheet 切换。
- 支持指定表头行。
- 根据表头列名自定义选择分组列。
- 根据表头列名自定义选择求和列。
- 按分组列完全一致合并记录，求和列使用 Decimal 精确汇总。
- 生成汇总结果预览。
- 复制汇总结果时写入 HTML 表格和纯文本，粘贴到 Excel 时尽量保留样式、列宽、行高和数据。
- 导出新的 `.xlsx` 文件，文件名为 `原Excel文件名_汇总.xlsx`，只包含一个 `汇总结果` sheet。

## 非目标

- 第一版不处理 `.xls` 老格式。
- 第一版不做跨多个 sheet 的合并汇总。
- 第一版不做用户账号、云端存储或服务端部署。
- 第一版不尝试 100% 复刻 Excel 复杂对象，如图片、图表、批注、公式依赖和条件格式。

## 技术方案

- 前端：React、TypeScript、Vite、Fluent UI React v9。
- 后端：Python、FastAPI、openpyxl、pydantic。
- 测试：pytest 覆盖 Excel 汇总核心和导出命名；Vitest 覆盖前端纯函数。

前端负责操作界面、表格预览、列选择、复制到剪贴板和下载触发。后端负责解析 Excel、抽取可预览数据和样式、执行汇总、生成新的 Excel 文件。

## UI 风格

采用接近新版 Microsoft 365 Excel 的办公工具风格：浅色背景、Office 绿色作为强调色、顶部轻量命令栏、细网格线、简洁控件、低对比边框和克制阴影。页面以大面积表格画布为主，减少装饰性卡片，强调扫描效率和财务人员的日常可用性。

## 数据流程

1. 用户选择 Excel 文件。
2. 前端上传到本地 FastAPI。
3. 后端保存到临时目录，返回文件 ID、原始文件名、sheet 列表和默认 sheet 预览。
4. 用户切换 sheet 或表头行时，前端请求预览。
5. 用户选择分组列和求和列。
6. 前端提交汇总配置。
7. 后端读取对应 sheet，按配置生成汇总数据和结果样式。
8. 前端展示结果预览。
9. 用户复制结果或导出新的 Excel 文件。

## 样式策略

后端读取原 sheet 的列宽、行高、表头样式和数据行基础样式，转换成前端可渲染的 CSS 样式。汇总结果复用这套样式模型。导出 `.xlsx` 时再将样式写入 openpyxl worksheet。

复制到剪贴板时，前端生成带 `table`、`colgroup`、`tr`、`td` inline style 的 HTML，同时提供 tab 分隔纯文本。Excel 对剪贴板 HTML 的列宽和行高支持受版本影响，因此导出 `.xlsx` 是格式保真的主路径，复制是便捷路径。

## 错误处理

- 未选择文件时禁用处理按钮。
- 未选择分组列或求和列时提示。
- 求和列中的空值按 0 处理。
- 求和列中无法转换为数字的值按 0 处理，并在结果中返回警告。
- sheet 或列名不存在时返回明确错误。

## 验收标准

- 能上传包含多个 sheet 的 `.xlsx` 文件并切换预览。
- 能选择表头行、分组列和求和列。
- 能把同组数据汇总为一行。
- 导出文件名符合 `原Excel文件名_汇总.xlsx`。
- 导出的 workbook 只有一个 `汇总结果` sheet。
- 结果预览、复制 HTML 和导出 Excel 使用一致的基础样式。
- UI 看起来像清爽的 Office 工具，而不是通用后台模板。
